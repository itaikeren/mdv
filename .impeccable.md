# Impeccable Design Context

## Design Context

### Users
Developers (and, increasingly, their AI agents) who want a fast way to write, preview,
publish, and share markdown. Human visitors land on `/` signed-out while evaluating the
product; agents interact through the MCP endpoint. Context of use: a developer's desk,
usually a dark editor/terminal nearby.

### Brand Personality
Engineered, quiet, terminal-warm. The product feels like a well-made developer tool:
precise, unflashy, honest about being for people who live in editors. Confidence comes
from restraint, not decoration.

### Aesthetic Direction
**Polished hybrid terminal.** The app itself is a full terminal aesthetic (JetBrains
Mono / 0xProto everywhere, dark GitHub-terminal palette, single green accent, `--term-*`
tokens with a light theme variant). Marketing surfaces (the homepage) soften this:
a characterful grotesque (Schibsted Grotesk) for headlines and body copy, with the
monospace stack reserved for code, terminal windows, labels, and accents. Dark theme is
the default (audience + product context), light theme must keep working via the existing
`html.light` token swap.

- Accent: the existing terminal green (`--term-green`), used sparingly (~10% visual weight).
- Icons: pixel-art style (pixelarticons, MIT), inlined as SVG — matches the terminal DNA.
- Anti-references: generic SaaS landing pages (purple-blue gradients, glassmorphism,
  gradient text, identical icon-card grids, centered everything).

### Design Principles
1. **The landing is the product** — show the real split editor and a real agent/MCP
   session as believable mock windows with realistic content, not abstract art.
2. **Mono is seasoning, not the meal** — monospace for code/labels/terminal chrome;
   the grotesque carries reading-length copy.
3. **One accent, one theme system** — reuse `--term-*` tokens so the page works in both
   themes for free; green is the only accent color.
4. **Fast is a feature** — self-hosted fonts, inline SVGs, CSS-only animation, no new
   runtime dependencies; the page must not slow the app down.
5. **Left-aligned, asymmetric, rhythmic** — vary spacing for hierarchy; no identical
   card grids; break the grid deliberately for the hero and agent sections.
